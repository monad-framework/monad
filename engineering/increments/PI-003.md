# PI-003 — Executable Engineering Loop

**Status:** Forecast  
**Dates:** 2026-09-28 through 2026-10-25  
**Sprints:** SPRINT-007 through SPRINT-010

## Objective

Turn trusted semantic knowledge and change impact into conservative incrementality, explicit execution plans, native-tool execution evidence, a coherent CLI, and bounded AI-agent context under human-controlled authority.

## Capability sequence

1. Impact-path explanation and uncertainty hardening.
2. Incremental invalidation/update and stable fingerprints.
3. Execution-plan schema, planner and policy/authority first slice.
4. Native-tool adapter/runtime, failure semantics, verified cache and evidence.
5. Release 1 CLI integration.
6. Agent task/capability model, semantic context selection, context package and Codex export.

## Integrated PI scenario

Given a known repository state plus an authorized change/task, Monad:

```text
calculates semantic affected set
  → explains impact paths/uncertainty
  → updates only safe semantic dependencies
  → builds an inspectable execution plan
  → checks authority/policy
  → generates bounded agent context when requested
  → invokes real native tools
  → captures diagnostics and evidence
  → exposes the flow through the CLI
```

## Exit criteria

- [ ] Conservative uncertainty cannot silently narrow required work.
- [ ] Incremental semantic output matches correct full-rebuild semantics in the differential suite.
- [ ] Plans are deterministic, serializable, inspectable, and side-effect-free until execution.
- [ ] Native-tool execution has explicit working directory/environment/tool identity/failure semantics.
- [ ] Cache hits are verified against declared fingerprint semantics.
- [ ] CLI exposes the integrated Release 1 workflow with stable structured output/exit behavior.
- [ ] Agent context is minimal, attributable, capability-bounded, and excludes unauthorized sensitive content.
- [ ] PI integration/security/Definition-of-Done gates pass.

## PI decision

Proceed to release hardening only when the engineering loop is complete enough that later work is validation, packaging, documentation, dogfooding, and defect correction rather than missing semantic/execution architecture.
