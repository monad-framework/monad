# PI-002 — Semantic Kernel

**Status:** Forecast  
**Dates:** 2026-08-24 through 2026-09-27  
**Sprints:** SPRINT-002 through SPRINT-006

## Objective

Compile a representative repository's canonical engineering artifacts into a deterministic, provenance-rich Monad Semantic Graph and versioned KIR that users can validate, query, explain, and use for a first conservative change-impact calculation.

## Capability sequence

1. Workspace/configuration/artifact/tool discovery.
2. Semantic identity, normalization, hashing, source coordinates, provenance and diagnostics.
3. MSG ontology, graph construction, invariants, canonical snapshot and traversal.
4. KIR schema, canonical serialization, lowering, validation and compatibility.
5. Query/explanation plus Git change ingestion and first affected-set analysis.

## Integrated PI scenario

From a clean checkout of a reference repository:

```text
inspect workspace
  → inventory supported artifacts
  → assign identity/provenance
  → compile MSG
  → lower KIR
  → validate
  → query/explain relationships
  → apply/observe bounded change
  → compute and explain affected set
```

The same declared input state must reproduce equivalent graph/KIR semantics.

## Exit criteria

- [ ] Workspace and artifact discovery are deterministic and read-only.
- [ ] Stable identity/provenance contracts are implemented and property-tested.
- [ ] MSG construction/invariants/canonical serialization pass conformance fixtures.
- [ ] KIR is versioned, validated, and produced from MSG without source reparsing downstream.
- [ ] Query/explanation exposes provenance and relationship paths.
- [ ] First affected-set corpus has no known false-negative required validation in supported scenarios.
- [ ] Structured diagnostics cover known invalid/unsupported states.
- [ ] PI integration, machine sync, security and Definition-of-Done gates pass.

## PI decision

Proceed to PI-003 only when semantic impact is trusted enough to inform execution planning. If affected-set correctness is uncertain, harden the semantic kernel rather than allowing execution to depend on unjustified optimization.
