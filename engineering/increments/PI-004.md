# PI-004 — MVP Hardening and Release

**Status:** Forecast  
**Dates:** 2026-10-26 through 2026-11-22  
**Sprints:** SPRINT-011 through SPRINT-014  
**Forecast release:** 2026-11-23

## Objective

Turn the integrated semantic engineering loop into a release-quality MVP with reproducibility, conformance, security, performance, compatibility, packaging, dogfooding, documentation, provenance, support, rollback, and explicit release-readiness evidence.

## Capability sequence

1. Integrated reference repositories and clean-machine deterministic/reproducibility suite.
2. Security/fuzz/negative and supply-chain hardening.
3. Performance baselines and compatibility/migration verification.
4. Installable packaging and supported version/upgrade/rollback path.
5. Monad-on-Monad dogfooding.
6. Generated/user/maintainer documentation and bounded beta feedback.
7. Release CI, provenance, SBOM/signing/attestation as applicable.
8. Release-candidate freeze and formal readiness decision.

## Release guardrails

The PI may not trade away semantic correctness, deterministic behavior, secret/context safety, execution authorization, or reproducibility to preserve the forecast date. Scope is reduced before these gates are weakened.

## Exit criteria

- [ ] Every must-have MVP requirement traces to passing automated/manual evidence.
- [ ] Determinism/reproducibility reference suites pass from clean environments.
- [ ] No supported affected-set scenario has a known false-negative required validation without blocking uncertainty behavior.
- [ ] Security/supply-chain controls are verified and no unaccepted critical/high risk remains.
- [ ] Performance baseline and known scale limits are documented.
- [ ] Public CLI/config/graph/KIR compatibility expectations are explicit and tested.
- [ ] Installation, upgrade where supported, and rollback/recovery are demonstrated.
- [ ] Monad dogfoods meaningful portions of its own workflow.
- [ ] Documentation, known limitations, changelog/release notes, support and troubleshooting are ready.
- [ ] Release artifacts preserve source/toolchain/test/provenance metadata and verification.
- [ ] Product Owner and required Engineering/Security/Operations authorities record Release or Do Not Release.

## Closure

PI-004 closes with the MVP Release 1 decision, not simply the end of SPRINT-014. If evidence rejects the candidate, blockers return to the ordered backlog and a revised release forecast is created.
