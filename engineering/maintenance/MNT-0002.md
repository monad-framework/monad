# MNT-0002 — EOSV execution-bound evidence audit fingerprint mismatch

**State:** VERIFYING
**Type:** bug
**Area:** EOSV evidence freshness
**GitHub Issue:** #191
**Blocked Work:** WP-MVP-0002 EOSV verification

## Summary

Execution-bound EOSV evidence captured with `--execution` becomes stale immediately during the next evidence audit even when no governed, implementation, baseline, or workspace input has changed.

## Context

WP-MVP-0002 implementation merged through PR #190. Fresh Rust verification on merged `main` passes, and `./scripts/eos validate WP-MVP-0002 --profile wp --execution EXEC-0004` produces required integrity PASS plus execution-acceptance PASS. The immediately following strict evidence audit nevertheless marks the new execution-bound evidence stale.

## Root cause

`run_profile()` captures with `source_fingerprint(target, execution)`. `audit_evidence()` reconstructs with `source_fingerprint(row.get("execution") or row.get("target"))`, substituting the execution identifier into the fingerprint target field. The hashes therefore differ even when real source state is unchanged.

## Resolution

Audit with the same target/execution pair used at capture: `source_fingerprint(row.get("target", ""), row.get("execution", ""))`. Extend the EOSV freshness regression to exercise immediate execution-bound evidence audit parity and retained real-drift detection.

## Scope

In scope: `tools/eos/verification_v2.py`, `scripts/test-eosv-evidence-freshness.py`, this maintenance artifact, EOS control state, dependent evidence refresh, and machine projections.

Out of scope: WP-MVP-0002 product implementation, EOSE baseline semantics, #175, #176, #178, #181, and unrelated EOS refactoring.

## Additional root cause discovered during real-workflow verification

After PR #192 corrected target/execution reconstruction, the real WP-MVP-0002 EOSV workflow exposed a second self-reference in the same freshness defect: `workspace_hash()` excluded EOS control/evidence outputs but still included generated `machine/**` projections. EOSV captures evidence before machine-document synchronization, so the subsequent projection rewrite changed the execution workspace hash even though executable and governing source state was unchanged.

The execution workspace fingerprint must therefore exclude `machine/**`, consistent with non-execution source freshness, while retaining substantive source/workspace drift detection.
